# Spec

Features, untested parts and ideas, one paragraph per area. Moved out of `index.html` on 2026-11-23 so phones do not download it; keep it updated with every change.

Files: index.html (markup), style.css, app.js (data, import, rendering), cloud.js (accounts + sync), sw.js (service worker), manifest.webmanifest, icons/, vendor/xlsx.full.min.js (SheetJS 0.20.3, loaded on first Excel file), vendor/pdf.min.mjs + pdf.worker.min.mjs (pdf.js 6.5.438 legacy build, loaded on first PDF; not saved for offline until used once), vendor/tesseract.min.js + worker.min.js + tesseract-core-lstm.wasm.js + heb/eng.traineddata.gz (tesseract.js 7.0.0, text recognition for payslip pictures, about 7.5MB, loaded on first picture). Tests: npm test.

Installable app (PWA): manifest + icons, so it can be added to a phone's home screen or installed from Chrome/Edge. sw.js saves the app's files: the saved page is shown at once (a new deploy shows as the "Update available, Reload" notice), the app's files (the Firebase SDK in vendor/firebase/ is one of them) and fonts come from the saved copy. Firebase sign-in and data calls are never stored by it. The version after style.css, app.js and cloud.js and VERSION in sw.js are written by tools/stamp.mjs before every npm test; never edit them by hand. A new version shows on the next load; an app left open shows "Update available, Reload". On localhost the service worker is off unless the address has ?sw=1.

Content Security Policy (the meta tag in the head): the page may load scripts only from this site, styles and fonts from Google Fonts, and contact only Firebase sign-in and data (plus the local emulators' addresses). Tested: every test fails if the policy blocks anything (sign-in, sync, offline, payslip PDF and picture, Excel import and export, update notice all pass under it).

Backup reminder (2026-11-23): the Account (Backup) panel says how old the last "Download my data" is (S.bak, synced; the date is also inside the file), in red when there is none or it is over 31 days old. "Load sample data" in Import shows only while there are no purchases.

Storage: localStorage "spend-v1" in local-only mode; Firestore per account in cloud mode. No bank connection.

Top row (redesign part 1, 2026-11-18): "+ Add purchase" and one "More" menu (Import, Cards, Recurring, Budget, Report, Merchants, Account, then Theme and Delete all data; closes on a choice, outside click or Escape). Panels: Import, Cards, Recurring, Budget, Merchants, Account (cloud mode: sign out, Download/Restore, delete account; local-only mode shows it as "Backup" with Download/Restore only), Delete all (press twice).

Look (2026-11-18): "Copilot blue" palette in style.css (light and dark variables on :root), the summary is a card with a progress bar toward the budget (green, amber from 80%, red when over). Theme button in the More menu cycles Auto (follows the device, default) / Light / Dark; kept per device in localStorage "spend-theme" (not synced), applied by the first lines of app.js, the browser bar colour (theme-color metas) follows;  Expenses list shows the latest 5 of the month ("Show all" / "Show only the latest 5"); no limit while searching or filtering by a category; adding a purchase shows all. Untested: a real phone, the brief flash if Light/Dark is chosen against the device setting (the theme is applied when app.js loads, not in the head).

Import: CSV/Excel/pasted text. Finds each header row (several sheets are fine), uses the purchase date and the charged amount ("סכום חיוב", not "סכום עסקה"). Identical rows in one file are all kept; importing again skips only copies already saved on that card. Refunds come in as negative amounts. Installments ("תשלום 3 מתוך 5") are dated in their own month and labelled "3/5". The card's last 4 digits are read from the file to suggest a card name. A file covering several cards (a "4 ספרות אחרונות" column) puts each row on its own card (saved name with those digits, else the typed name for the main card, else "Card 1234") (2026-11-22). Standing orders ("הוראת קבע") not yet in Recurring are offered after import as one-tap monthly bills; such a bill starts this month, its rows are marked "not on a statement yet" and a row of the next statement on the same card within 7 days, with the same amount or description, replaces them. A typed card name ending in 4 digits takes only those digits; the chosen counting rule also goes to cards the import creates. Not handled: a standing order bill whose description changes between statements. A row paid by phone ("תשלום בנייד") prefers a phone purchase from a Wallet notification when matching, other rows prefer the others. A purchase made in another currency keeps its original amount ("סכום עסקה מקורי" + currency) next to the charged shekels. A bank-style file (most amounts negative) imports the negatives as spending and the positives as income. A purchase edited after import remembers its imported values (src), so importing the same file again does not add it back. Tested on real Isracard and Max files (2026-11-15).

Payslip (תלוש שכר): pick the PDF in Import, or paste its text. Only the net pay ("נטו לתשלום"), the slip's month and its issue date are read; a line shows them with a date box and "Add as income", which adds one income row "Salary MM/YYYY". The same slip is not added twice. Nothing else from the slip is saved. A picture of the slip (photo, screenshot, JPEG/PNG) is read by text recognition inside the browser, nothing is uploaded: Hebrew pass for the label, then the numbers on that row are read again as digits only when the first pass did not give a proper amount. A message asks to check the amount. A password-locked PDF gets a message.

Cards: S.cards[name] = percent that counts (full 100, half 50, custom, not counted 0). Rename a card in the Cards panel. A joint card is a card set to half.

Summary: spent, In and Left over (when the view has income), a figure per card (when more than one), currency.

Add expense and income (2026-11-19): "+ Add expense" sits above the expense list (the top "+ Add purchase" and "+ Add income" buttons are gone). Choosing "Income" in a row's category box turns it into plain income (amount positive, no card, no split, no currency); a category on an income row still makes it a payback. The report always shows Spent, Income and Left over.

Main screen (2026-11-19): with a budget set (one month, All cards) under the bar a small line says what is left of it (red "over" when past it); when Buying in is not the home currency a trip strip (#trip) shows what was spent in it. How to page (2026-11-19): More, How to; topic buttons (#p-how, data-how / data-h), one topic at a time; keep the text in step with the features. Multi-currency fixes (2026-11-19): a row's date change fetches the rate again unless fx.m (hand-set); a statement can be imported in another currency (box next to the card rule); changing Home currency asks to convert all amounts (undo); fillRates() fills rows saved without a rate.

Multi-currency (2026-11-19): Account has Home currency (everything is shown in it) and Buying in (the currency new purchases are entered in, e.g. EUR on a trip). A row in another currency keeps t.fx={c,a,r} (original amount, rate) with amt=a*r in the home currency, so calc()/v() are unchanged; the row shows the original amount, a currency box (switch it if the input was wrong) and the rate. Rates: api.frankfurter.dev (ECB), for the purchase date, cached on the device; offline = last known rate, else type it. Editing the home amount changes the rate. Changing the home currency later does not convert old rows. Tested with a mocked rate service. Phone items: a quick-add amount is in "Buying in" (or the item's own "cur" code); a notification naming another currency (€50, USD 12,5) is saved in it and the shekel value is looked up on arrival; a shekel amount stays shekels.

Income: a row with inc:1 and a positive amount ("Income (a category-box choice)", recurring income, positive rows of a bank file). No category = income, counts toward In. With a category = a payback, lowers that category and Spent in full. Card rules never apply to income. calc(rows) in app.js is the single definition of spent / in / per category / per card.

Budgets (Budget panel): S.budget = {total, cats:{name:amount}}, monthly, saved with the settings. Shown with one month picked and no card filter: "X left of Y" under Spent, category bars fill against their budget (amber from 80%, red when over). Budgets follow a renamed category.

Report button (types: Monthly, Selected expenses = what the filters and search show, Trend = last 6 or 12 months): a print-ready monthly (or yearly, or all-time) report with totals, against budget and last month, income and left over, categories, cards, top 10 merchants, 5 largest, recurring bills and the full list (options: list on/off, ignored rows on/off); Print / Save as PDF uses the browser, Export to Excel saves the rows. Merchants panel (learned merchant to category, change or forget), All of YEAR entries in the month picker (budgets hidden), a Note on each purchase (searchable). Categories: Compare button (two months side by side per category with the change, a total row, an In row when there is income, and a 12-month trend strip; tap a month to pick it; neutral colours, not saved). Editable, add, bars (click to filter), sort by size or own order (drag grip), colors stay per category. Other = catch-all. New accounts start with 9 default categories. Accounts that already saved their categories keep them. Utility and home-shop keywords are extra keyword groups of Rent & payments and Shopping in CATS (app.js), checked in their old place in the order.

Expenses: inline edit, add, month + card filters, Search box (every word must appear in description, category, card or amount; shows "N found, ₪X"; summary and bars keep showing the month; not saved), column sort, Ignore checkbox. A negative amount is a refund and lowers the totals. An added purchase left empty is dropped on the next start.

Categorizing: learned merchant first, then EN + HE keywords, then the issuer's own category column if the file has one (Max); anything else stays in Other for manual sorting.

Recurring (monthly, card "Recurring" unless another is chosen): starts empty; the user adds their own bills or income (Bill / Income choice) in the Recurring panel. The form is hidden behind a "+ Add recurring" button (Cancel closes it; adding closes it). A bill starts in the month it was added; its month's row is added when the app loads and also when an app left open returns to the front on a later day (visibilitychange). Tested.

Accounts + cloud sync (Firebase, see docs/backend.md): only active when FB_REAL is set or on localhost (emulators). Sign in (with a Show/Hide button for the password), Create account (needs invite code), Forgot password, Account panel (Sign out, Download my data, Restore from file with second press + undo, Delete my account with password + press twice). Data per account in Firestore, live sync between devices, "Saved / Saving… / Offline" status.

FB_REAL is set (project spending-management-608d5), so the live site requires sign-in.

Tested automatically on the emulator (npm test): sign up/in, wrong invite, two-device sync, per-account privacy, delete all, download + restore, delete account, income and budgets on a second device and after signing out, import cases above, income by hand, paybacks, recurring income, budgets, payslip (a made-up PDF, a made-up JPEG and pasted text), re-import after an edit, installable files, update notice, opening offline and syncing an offline edit.

Names: a merchant, card or category may be called anything, including "constructor" or "__proto__" (the lookup maps have no prototype, fixMaps() in app.js; tested).

Navigation (2026-11-19): every page and the report close the same way, "‹ Back" with the page name at the top left (the report's own Close button is gone; Back from a report opened on a page returns to that page). More opens from everywhere (on a page or the report the top bar keeps only its menu). The phone's back gesture / the browser's Back closes whatever is open (page, report, add sheet, More menu) and returns to the main screen instead of leaving the app: navSync() keeps one extra history entry while something is open, popstate closes it all. On the phone a page has no card frame around it. In-place modes keep "Done" (Compare, Edit), forms keep "Cancel" (add sheet, recurring).

One mode at a time (2026-11-19): Compare replaces the category list and hides Bars, the sort buttons and Edit (its button reads Done); Edit hides Compare and Bars; opening either clears a category filter; Compare shows only with two months of data, "Bars" only when a category has a budget.

Motion and polish (2026-11-19): the big number counts to its new value and bars grow from where they were (motion() in app.js); new purchases glow in, deleted ones slide away; panels, the More menu and the Undo message ease in and out; buttons press in; "Saved" gets a tick; the work timer's colons blink and its strip has a breathing dot; loading shows shimmering shapes; category icons sit on rounded colour tiles; no blue tap flash or focus ring on tap (a keyboard still gets the ring). Phone (640px and under): a bottom bar (Home, Work, More, Account; More opens as a sheet above it and holds Report; Account is not repeated in it), every panel opens as its own page that slides in under a "‹ Back" bar (body.pg hides the main screen), a round + button on Home (and "+ Add expense") opens a sheet that slides up: Expense/Income, big amount in the Buying-in currency, description, category (Auto = guessed from the description), card, date, Save (with Undo; foreign amounts get the day's rate); the sheet rides above the on-screen keyboard (sheetFit() reads visualViewport) and drops back when it closes, and swipe a purchase left past 90px to delete it (with Undo). One standard for every change of screen (2026-11-19, second pass): everything that appears eases in the same way (panels, report, compare, recurring form, help topics, strips, Rate and rules, the app after loading); the home screen eases back in after the report; a panel closed to Home fades away (switching panel to panel swaps at once); the More menu fades out when closed; a new filter, month, sort, Show all or the category Edit view fades the list in; + Add expense glides to the new row and it glows (the glow survives a re-draw); the theme switch cross-fades the colours. All motion is off when the device asks for reduced motion, and under test automation (navigator.webdriver) so tests read final values. Not checked on a real phone; the browser pane runs at ~2 frames a second, so the smoothness itself was not seen.

Work log (2026-11-19; totals added 2026-11-20): the page shows This week / This month / not in income yet, and a line per month with Add month to income. Timer from a phone button with the app closed: a MacroDroid item {work:toggle,date,time} in the phone inbox (workInbox(), docs/phone.md); applied when the app next opens, oldest first. Links for a phone automation or NFC tag: open the app address followed by #add, #add-income, #work or #work-toggle (starts or stops the timer). Original description: a Work button next to More opens a page with a big running timer (HH:MM:SS), Start/Stop, the amount earned so far, and a list of sessions (edit start/end, Holiday tick, delete with Undo, add by hand). While running, a strip on the main screen shows the time and opens the page. Stored in S.work (rate, rules, log) inside the settings document, so it syncs with no rules change. Pay (workDay() in app.js): sessions that start on one date are one work day, no midnight split; first 8h 100%, next 2h 125%, then 150%; hours inside the Shabbat window (Fri 18:00 to Sat 19:00, editable) or in a Holiday session 150%, their overtime 175% / 200%. Each session keeps the rate and rules it started with. Nothing reaches income by itself: "Add to income" per session or all (row id work-<session id>, so never twice). Not done: weekly 42h limit, unpaid breaks, a built-in holiday list, rate in another currency after the home currency changes. Not tested on a real phone. Voice button (2026-11-20): an inbox item with say (speech-to-text) is an expense (amount + place, parseSay) or a shift start/stop command; not yet tried on a phone.

Dates are the device's local date everywhere (ymd() in app.js), tested with the clock set to 00:30 Israel time.

The user signed in on the live site under the policy on 2026-11-16 and it loaded and saved.

Checked 2026-11-18 (script in a real browser, partly now in npm test): a split and removing a part (with Undo) reaching a second device, the report and alert in dark and light at 420px, a made-up password-locked PDF, split on a refund, split parts after renaming or deleting their category and Undo, category drag (kept after reload), recurring bill add/delete/Undo/no duplicate after reload, .xls file, pasted text with a refund word (refund, reversal, זיכוי read as negative), pace on the 1st, mid-month, last day and 31 Dec.

Budget alerts (2026-11-18): under the budget line, "Over budget: …" (red) and "Near the limit (80%+): …" list the categories past 100% and between 80% and 100% of their budget; shown wherever budgets show (one month, all cards). The line is always there while it applies. Also a notice at the top for 8 seconds (#bnote, budNote() in app.js) when a category, or the whole budget, rises to 80% or over 100% compared with the last time that month was drawn with the same purchases (an edit, an import or a phone item arriving); not on the first draw of a month. The whole budget near the limit (80%+) is on the alert line too (#totalalert). Pasted text: a minus sign or brackets in front of an amount (-80, (80.00)) is a refund, except in a file of 3+ rows where most are negative (bank-style: negatives are spending).

Phone layout (under 640px): each expense is a card (description and amount on top, date, category and card below, Ignore and delete at the bottom), sort buttons wrap above, tools row scrolls sideways, 44px touch targets, 16px inputs, safe-area padding; text fields use dir=auto for Hebrew. 640-900px keeps the desktop table, which scrolls inside its box.

Split (2026-11-16): choosing "Split…" at the bottom of a purchase's category box adds a part (category + amount) under it; saved as t.split = [{cat,amt}] on the row, amounts before the card rule. The rest of the amount stays in the row's own category ("₪X stays in ..."). A part can take at most what is left of the amount; editing the amount below the parts, or flipping its sign, drops the split. Only the per-category numbers change (bars, budgets, Compare, reports): Spent and the per-card figures are the same as without a split. The category filter shows a split purchase under each of its categories; reports and the Excel export show "A + B". Income and paybacks cannot be split. Renaming or deleting a category follows into the parts. Tested (local mode): split, the limit, half-counted card, reload, amount lowered.

Tags (2026-11-16): a #word in a purchase's note is a tag (nothing extra is saved; letters, digits, _ and -, any language, case ignored). A row of tag buttons above the list shows each tag in the month with its spent total (by v(), ignored rows left out); pressing one filters the list (it puts #tag in Search, which matches the whole tag). The monthly report has a "By tag" section. Tested.

Icons (2026-11-16): each category has an emoji icon. The starting categories have one (ICON/ic() in app.js); pressing the icon in the category list opens a picker (a grid, none, or type your own); the choice is saved in S.icon[category] ("" = none), follows a rename, and shows in the category list (also on phones), the category boxes and the filter chip. Cursor: plain text and numbers show the normal arrow (body{cursor:default}); only things you can click or type in show the hand or text cursor. Tested (local mode): starting icon, pick, type, none, reload, rename.

Month start day, fixed charges, pace (2026-11-16): Budgets panel "Month starts on day" (S.mstart, 1 to 28, default 1) makes every month run from that day to the day before the next, named by its dates (pk(date) gives a period key, mrange(m) its first and last day; cloud.js still stores calendar months, nothing there changed). Fixed charges are worked out, not saved (fixedSet()): same words, one row a month, about the same amount (within 15%) in 3 or more months, or a recurring item. The top shows "Fixed X · everything else Y". For the current month with all cards: a day allowance ("X a day for N days left", after the fixed charges still to come, shown when a budget is set), a forecast ("Z by the end of the month at this pace" = spent + fixed still to come + the other spending's daily pace), "Ahead of pace" for categories whose free part (budget minus their fixed charges) is used faster than the month passes, and a "still to come" list of fixed charges seen last month and not yet due. No alert when a fixed charge changes price (asked not to). Tested (local mode).

Opening (2026-11-16): the page opens on the current month (or the latest month with data) instead of All time, so budgets and pace show without picking a month. Quick add (a button and an app-icon shortcut) was removed 2026-11-18: the MacroDroid popup and Google Wallet macros do its job on the phone, and "+ Add purchase" does it in the app.

Main screen trimmed (2026-11-18): the per-day, end-of-month pace, "Fixed X / everything else Y" and fixed-charges-to-come lines, the In and Left over numbers, the currency box and the help text under Expenses were removed (the code is in git commit edc2d55 if wanted back). Income and left over live in the Report. The currency symbol is now in the Account (Backup) panel. Main-screen categories (2026-11-18): the main screen lists only the picked categories (S.catPick, saved and synced; Undo) or, with none picked, the 4 biggest of the period, in the chosen order (By size / My order). "All categories · Edit" opens every row with rename, icon, drag, delete and a ☆ to pick; "Back to the 4 biggest" clears the pick. A rename keeps the pick.

Bars (2026-11-16): the "Bars: amount / budget" button above the categories (S.barMode, saved) picks what the category bars show: every bar against the largest category, or a bar with a budget filling toward it (one without a budget stays empty). The "of ₪X" note next to the amount is always shown; the warning colour (rose, --warn) starts at 80% of a budget and red (--bad) when over, in both modes.

Cards panel has "Add card" (2026-11-17). Card of a purchase (2026-11-17): a dropdown of saved cards plus "＋ New card…" (asks for a name).

Default card (2026-11-17): Cards panel star button sets S.defCard, used by the phone inbox (else the latest card). Google Wallet notifications: amount, merchant (title), card by the issuer word after "with" or last 4 digits (inboxRow). More Health keywords (hair, beauty, massage, therapy). UNTESTED on a phone: the Wallet macro (docs/phone.md).

Phone inbox and statement matching (2026-11-16): Account panel "Add from your phone" makes a key and shows an address; a phone automation that sends the key can add a purchase without signing in or opening the app (details and rules: docs/backend.md). Rows from the phone are marked t.auto=1 and show "not on a statement yet" for 40 days; when a statement row with the same amount within 2 days is imported (same card first, then any card) the two become one row: the statement's date, description and card, your category, note and split (your own description moves to the note). The import message says "matched N you had already added". Tested on the emulator: key on/new/off, wrong key refused, typed item, raw notification text (English and Hebrew shape, made-up), merge, no double rows after reload. UNTESTED: the real project's address from a real phone, MacroDroid itself, a real Google Wallet notification's wording, two devices open at once when an item arrives.

Undo: 8s button + Ctrl/Cmd+Z, session only.

Speed (2026-11-18): measured with a script (phone-like: 4x slower CPU, 150ms delay) the page took about 1s to show your data; most of it is Firebase starting (checking the saved login with Google, then reading the saved data). Changes: the saved page is shown at once (before it waited for the network, up to 4s on a bad line; measured on a server with 250ms per answer: 700ms to 430ms to the totals), the Firebase files are preloaded and the connections to sign-in and the database start while the page loads (<link rel=modulepreload/preconnect>; nothing is sent). Tried and dropped: drawing a saved copy of the data before Firebase answers (the drawing itself is the slow part, so it made the total longer). NOT measured: the real Firebase servers from a real phone.

Card names (2026-11-18): not case sensitive. A name typed in Import, the New card box, the Cards panel or a phone item that matches an existing card ignoring upper/lower case ("max" for "MAX") is that card (canon() in app.js); a rename that only changes the case is allowed. Cards already saved under two spellings are NOT merged automatically: rename one to the other's spelling is refused as already used, so change the rows or delete one by hand.
